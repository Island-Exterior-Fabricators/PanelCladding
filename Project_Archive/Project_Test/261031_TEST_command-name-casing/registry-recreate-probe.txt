Registry CommandList upgrade probe, 2026-10-31 (Windows PowerShell 5.1, scratch HKCU key, removed afterwards)

Question: after an upgrade from 1.2.5, does CommandList keep the old spelling (PCEditor) next to or
instead of the new one (PCeditor)? Registry value names are case-insensitive.

Steps, mirroring Install-PanelCladdingEditor.ps1 (New-Item -Force, then New-ItemProperty per command):
  New-Item -Path HKCU:\Software\ClaudeScratchCasingProbe\CommandList -Force
  New-ItemProperty ... -Name PCEditor -Value '2;PCEditor' -PropertyType String -Force
  New-Item -Path HKCU:\Software\ClaudeScratchCasingProbe\CommandList -Force
  New-ItemProperty ... -Name PCeditor -Value '2;PCeditor' -PropertyType String -Force
  (Get-Item ...).GetValueNames()

Result:
  PCeditor

The installer's New-Item -Force recreates the key, so an upgraded registration holds only the new
spellings. The installer's validation compares names and values with PowerShell's case-insensitive
operators (-notin, -ne), so a 1.2.5 registration also still validates against the new list.
The agent session's registry view is not proof of host persistence; this probe shows PowerShell
semantics only. Installation and host attestation are not part of this change.
